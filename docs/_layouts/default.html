{%- comment %} THE SENTINEL SPLIT, and it exists so that ONE page can carry an interactive app without the markdown source carrying a line of HTML or Liquid. docs/standards/WHICH-STANDARDS-APPLY.md is also converted to Word by pandoc and pinned by tests/test_word_copies_track_the_markdown.py, so raw markup in it would appear as garbage in the .docx -- or, worse, be silently dropped along with the prose around it. An HTML comment costs the markdown one invisible line: it renders as nothing on GitHub, and pandoc's docx writer emits nothing for it (verified against the shipped command, not assumed). THE ABSENT CASE IS IDENTITY. Liquid's `split` on a string that does not occur returns a one-element array, so for the twenty other pages parts[0] is the whole document and there is no parts[1]. The size test below is there to make that legible rather than to make it true. THE FALLBACK IS DELIBERATE. kramdown is expected to pass a block-level HTML comment through to the rendered HTML, but nothing in tests/ builds this site, so a change in that behaviour would drop the app off the page with every gate still green. So: if the page IS the routing page and the sentinel did NOT survive, the include is emitted after the content instead. Placement degrades; the feature does not vanish silently. {%- endcomment -%} {%- comment %} ON-THIS-PAGE CONTENTS, BUILT HERE AND NOT BY A SCRIPT. WHY NOT JAVASCRIPT. assets/style.css states the rule: the selector may run a script because the answer it filters is complete before any script runs, and "if a future feature cannot say that second sentence about itself, it does not get a script either." A script-built table of contents cannot say it -- without the script there is no list at all. So it is built here, at build time, and is complete in the served HTML. WHY NOT `{:toc}`. kramdown's marker would have to be added to each markdown file, and fourteen of those are converted to Word by pandoc and pinned byte-for-byte by tests/test_word_copies_track_the_markdown.py. The marker renders as a stray list item in the .docx. A layout costs the markdown nothing.
