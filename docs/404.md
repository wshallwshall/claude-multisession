# Page not found

There is no page at that address on this site.

**A `docs/` prefix is the usual cause.** This site is built *from* `docs/`, so every page is served
at the root: `/CONCEPTS.html` resolves and `/docs/CONCEPTS.html` does not. A path copied out of the
repository keeps the prefix and misses.

**The host changed on 2026-08-10**, and the paths changed with it. Pages that sat under
`/claude-multisession/` now sit at the root, so `.../claude-multisession/CONCEPTS.html` is
[CONCEPTS.html](CONCEPTS.md) here.

**One page on this site was renamed.** The framework page was called CHORUS for thirteen hours on
2026-08-13, and is now [The KORUS framework](KORUS.md).

The landing page was split up on 2026-08-16. Its address did not change and it still answers; three
sections became pages of their own: the install procedure is [Quickstart](QUICKSTART.md), the limits
are [Limits and requirements](LIMITS.md), and the inventory is [Every script](SCRIPTS.md).

- [Start at the front page](index.md). It routes to every page on this site.
- [FAQ](FAQ.md) answers the question that usually decides things: whether you need this at all.
- [Concepts](CONCEPTS.md) is the model the rest of the site assumes.

## Why this page exists at all, which is not obvious

Without it, this site answers **every** unknown address with the home page and a `200`, Cloudflare
Pages' default for a project with no `404.html`. A reader gets a plausible page, not an error; a
check asking "does this URL work" gets a `200` that means nothing.

**A broken link and a working one become indistinguishable from both ends.** That is the failure
this project's documents are about, **so the site hosting them should not ship it.**

Measured on 2026-08-10 against the sibling site that moved first: with no `404.html`, a nonexistent
address returned `200` and bytes identical to the home page. With one, it returns a real `404`. The
old GitHub Pages host returned a real 404 on its own, so the move introduced this regression.

**You are reading this in a browser, which does not show you the status code.** Read it directly:

```
curl -sI "https://claude-multisession.pages.dev/no-such-page-$(date +%s)" | head -1
```

`HTTP/2 404` is the healthy answer. `HTTP/2 200` means this control is off, and every dead link into
the site now reports success. The random suffix matters: a fixed path can be answered from
Cloudflare's edge cache.

**Nothing here checks that this file still exists.** The gates build their page list from what git
tracks, so deleting it removes the page *and* the only thing that would have failed. The site
returns to answering `200` for everything, every check still green -- this page's subject, aimed at
itself.
